# Static vs Dynamic диспетчеризация в Rust

## Что такое диспетчеризация

**Диспетчеризация** — механизм выбора **какой именно** метод вызвать. В Rust два подхода:

| | **Static (статическая)** | **Dynamic (динамическая)** |
|---|---|---|
| Механизм | Generics + мономорфизация | `dyn Trait` + vtable |
| Когда решается | **Компиляция** | **Runtime** |
| Синтаксис | `fn f<T: Trait>(x: T)` | `fn f(x: &dyn Trait)` |
| Скорость | **Быстрее** | Медленнее |

## 1. Static диспетчеризация (generics)

```rust
fn sum_static<T: Op>(x: &T, y: &T) -> i32 {
    x.run() + y.run()
}
```

### Как работает

1. Компилятор **видит** `sum_static::<A>` и `sum_static::<B>`.
2. **Создаёт** отдельную копию функции для **каждого** `T`.
3. В **каждой** копии вызов `x.run()` — **прямой** (не через указатель).
4. Компилятор **знает** точный тип → может **инлайнить**.

### Мономорфизация

```
sum_static::<A>(a: &A, a1: &A) -> i32 {
    A::run(a) + A::run(a1)   // ← прямой вызов
}

sum_static::<B>(b: &B, b1: &B) -> i32 {
    B::run(b) + B::run(b1)   // ← прямой вызов
}
```

**Одна generic-функция** → **много** конкретных копий в бинарнике.

### Использование

```rust
let a = A;
let a1 = A;
println!("{}", sum_static(&a, &a1));   // 2

// ✅ Оба аргумента — одного типа
sum_static(&a, &a1);

// ❌ Нельзя разные типы
// sum_static(&a, &b);   // ошибка компиляции
```

**Ограничение:** оба аргумента — **одного** конкретного типа `T`.

## 2. Dynamic диспетчеризация (`dyn Trait`)

```rust
fn sum_dyn(v: &[Box<dyn Op>]) -> i32 {
    v.iter().map(|x| x.run()).sum()
}
```

### Как работает

1. **`Box<dyn Op>`** — **толстый указатель**: указатель на данные + указатель на **vtable**.
2. **vtable** — таблица методов для **конкретного** типа.
3. **Вызов** `x.run()` → **косвенный** через vtable.
4. Компилятор **не знает** точный тип → **не может** инлайнить.

### Схема памяти

```
Box<dyn Op>:
+----------------+----------------+
| ptr to data    | ptr to vtable  |   ← 16 байт (fat pointer)
+----------------+----------------+
        |                 |
        v                 v
    [A data]         [A vtable]:
                     +---------------+
                     | run() -> ...  |
                     +---------------+
```

### Использование

```rust
let a = A;
let a1 = A;
let b = B;

// ✅ Разные типы в одной коллекции
let v: Vec<Box<dyn Op>> = vec![
    Box::new(a),
    Box::new(a1),
    Box::new(b),
];

println!("{}", sum_dyn(&v));   // 4
```

**Ключевое:** можно **смешивать** разные типы в одной коллекции.

## Плюсы и минусы

### Static dispatch (generics)

**Плюсы:**

- ✅ **Быстрее** в рантайме (прямой вызов).
- ✅ **Inlining** — компилятор оптимизирует.
- ✅ **Мономорфизация** — специализированный код.
- ✅ **Нет** накладных расходов на vtable.

**Минусы:**

- ❌ **Раздувает** бинарник (копии для каждого `T`).
- ❌ **Увеличивает** время компиляции.
- ❌ **Нельзя** смешивать типы в коллекции.
- ❌ **Больше** кода в кэше инструкций.

### Dynamic dispatch (`dyn Trait`)

**Плюсы:**

- ✅ **Меньше** бинарник (одна копия функции).
- ✅ **Быстрее** компиляция.
- ✅ **Гетерогенные** коллекции (`Vec<Box<dyn Trait>>`).
- ✅ **Плагины** и **конфигурация в runtime**.

**Минусы:**

- ❌ **Медленнее** в рантайме (косвенный вызов).
- ❌ **Нет** inlining.
- ❌ **Vtable** — дополнительная индирекция.
- ❌ **Нельзя** вернуть `dyn Trait` по значению (только `Box<dyn Trait>`).

## Сравнительная таблица

| Аспект | Static (generics) | Dynamic (`dyn`) |
|---|---|---|
| **Скорость** | ✅ Быстрее | ⚠️ Медленнее |
| **Inlining** | ✅ Да | ❌ Нет |
| **Размер бинарника** | ❌ Больше | ✅ Меньше |
| **Время компиляции** | ❌ Дольше | ✅ Быстрее |
| **Гетерогенные коллекции** | ❌ Нет | ✅ Да |
| **Смешивание типов** | ❌ Нет | ✅ Да |
| **Плагины** | ❌ Нет | ✅ Да |
| **Vtable** | ❌ Нет | ✅ Да |
| **Fat pointer** | ❌ Нет | ✅ Да (16 байт) |

## Когда использовать

### Static dispatch (generics) — **по умолчанию**

- **Типы известны** на этапе компиляции.
- **Маленький** набор типов.
- **Производительность** критична.
- **Нет** гетерогенных коллекций.

```rust
fn process<T: Op>(x: T) { ... }
```

### Dynamic dispatch (`dyn Trait`)

- **Плагины** — типы **неизвестны** заранее.
- **Гетерогенные** коллекции — **разные** типы вместе.
- **Конфигурация** в runtime.
- **Большой** набор типов → **экономия** бинарника.

```rust
fn process(x: &dyn Op) { ... }
let v: Vec<Box<dyn Op>> = ...;
```

## Практические рекомендации

> **a)** Если типы **известны** и набор **маленький** → **generics**.
> **b)** Если **плагины**, **гетерогенные коллекции**, **конфигурация в runtime** → **`dyn`**.

### Дополнительно

- **`dyn` + generics** — можно комбинировать.
- **`Box<dyn Trait>`** — владение.
- **`&dyn Trait`** — заимствование.
- **`impl Trait`** — синтаксический сахар для generics.

## Пример: комбинация

```rust
// Generic-функция (static)
fn run_all<T: Op>(items: &[T]) -> i32 {
    items.iter().map(|x| x.run()).sum()
}

// Динамическая функция (dynamic)
fn run_all_dyn(items: &[Box<dyn Op>]) -> i32 {
    items.iter().map(|x| x.run()).sum()
}

fn main() {
    // Static: один тип
    let a_items = vec![A, A, A];
    println!("{}", run_all(&a_items));   // 3

    // Dynamic: разные типы
    let dyn_items: Vec<Box<dyn Op>> = vec![
        Box::new(A),
        Box::new(B),
        Box::new(A),
    ];
    println!("{}", run_all_dyn(&dyn_items));   // 4
}
```

## Сводная таблица

| Сценарий | Рекомендация |
|---|---|
| Известный тип | `T: Trait` |
| Маленький набор типов | `T: Trait` |
| Большой набор типов | `dyn Trait` |
| Гетерогенные коллекции | `Vec<Box<dyn Trait>>` |
| Плагины | `dyn Trait` |
| Критична производительность | `T: Trait` |
| Критичен размер бинарника | `dyn Trait` |
| Критично время компиляции | `dyn Trait` |

## Итог

- **Static dispatch** — generics + мономорфизация.
  - **Плюсы:** быстрее, inlining, специализация.
  - **Минусы:** раздувает бинарник, дольше компиляция, нет гетерогенности.
- **Dynamic dispatch** — `dyn Trait` + vtable.
  - **Плюсы:** меньше бинарник, гетерогенные коллекции, плагины.
  - **Минусы:** медленнее, нет inlining, fat pointer.
- **По умолчанию** — **static** (generics).
- **`dyn`** — когда нужны **разные** типы **вместе** или **runtime**-конфигурация.
- **Rust** позволяет **комбинировать** оба подхода.
- **Правило:** «Типы известны → generics. Типы неизвестны → `dyn`.»
